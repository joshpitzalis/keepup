# One delayed check

1. Run `node <skill-directory>/scripts/keepup.mjs status --json`. Use only the current learner's `files` whose `due` is true. Choose one, preferring the oldest `lastQuiz`, then debt. If none is due, say “No delayed check is due” and stop without logging evidence.
2. Read the file privately and inspect the learner's prior quiz concepts in `<state>/events.jsonl`. Ask exactly one code-checkable question about a previously tested concept, using a different example or path. Ask the learner to answer from recall without opening the file. Wait for the answer; do not show a walkthrough, answer or explanation first.
3. Compare the actual response with the current code. Log exactly one `quiz` event with a fresh retry id, `phase:"check"`, one file and one answer carrying `file`, `concept`, `question`, the learner's verbatim `answer`, and boolean `correct`. Do not attach a closed kata number. On an uncertain write, retry the same id and payload. If the CLI says no check is due, refresh status and stop; never relabel an immediate quiz as delayed evidence.
4. Give the correct explanation after recording the response, then run status again. Report correctness, resulting state, accuracy, mind and cognitive-debt change. An incorrect check is still useful evidence; never change its correctness to award verification.

The CLI enforces a full 24-hour interval and a later UTC date since the latest pre/post quiz not consumed by a delayed check. A correct qualifying check grants verification. A wrong check consumes the due occurrence without granting verification; it retains earlier genuine verification. Previously verified files below 70% accuracy become due seven days after their latest qualifying check, including practised files that have passed a delayed check. A new pre/post quiz starts a fresh one-day interval for the initial-quiz rule; it never postpones an already-due seven-day weak-verification check. Practice alone does not mean verified.
